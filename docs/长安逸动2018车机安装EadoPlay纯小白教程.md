# 长安逸动 2018 车机安装 EadoPlay：纯小白完整教程

> 这份教程写给完全不懂 ADB、安卓命令和编程的车主。
>
> 已验证车型：2018 款长安逸动原厂 Android 4.4.2 车机。
>
> 目标：先由车主完成车机设置、下载文件和连接电脑，再把电脑上的安装步骤交给能够操作本机终端的 AI 完成。

## 先看懂整个流程

你不需要 root 车机，也不需要破解系统。整个过程可以简单理解成：

```text
在车机上打开 USB 调试
→ 把车机切换成 Device 模式
→ 用双 USB-A 公对公数据线连接车机和电脑
→ 在电脑上下载 ADB 工具和 EadoPlay 安装包
→ 确认车机允许这台电脑调试
→ 把本文最后的提示词交给 AI
→ AI 先检查连接，再安装并验证 EadoPlay
```

这里的 ADB 是电脑控制安卓设备的官方调试工具。它相当于电脑和车机之间的“操作通道”。

这台原厂车机没有破解时，直接点击 U 盘里的 APK 会提示“应用未授权”或 `not auth`，标准的 `adb install` 也会被厂商鉴权拒绝。因此本文不再尝试普通安装，而是在确认 ADB 连接和工程权限正常后，直接使用已经在本车验证过的 `/data/app` 安装方式。

如果某台车机已经破解到可以直接安装第三方 APK，那么直接使用 U 盘或普通安装即可，也不需要这份教程。

## 一、开始前要准备的东西

请准备：

1. 一台 Windows 电脑；
2. 一根**双 USB-A 公对公数据线**，也就是两头都是 USB-A 公头，并且内部具备数据传输线路；
3. 可以正常供电并操作的车机；
4. EadoPlay 的 APK 安装包；
5. 能够操作你电脑终端的 AI，例如当前具备终端操作能力的 Codex。普通网页聊天机器人如果不能操作电脑，只能告诉你命令，不能代替你执行。

操作时请把车辆停稳。不要在驾驶过程中设置车机或连接电脑。

### 需要哪一种数据线

本车连接电脑调试使用的是**双 USB-A 公对公数据线**：

```text
车机 USB-A 接口 ←→ USB-A 公头——数据线——USB-A 公头 ←→ 电脑 USB-A 接口
```

购买或寻找线材时要看清楚以下关键词：

- USB-A 对 USB-A；
- 双 A 口；
- 公对公；
- 支持数据传输。

不要使用常见的 USB-A 转 Type-C、USB-A 转 Lightning、USB-A 转 Micro-USB 手机充电线，也不要使用只有供电线路的“双 A 口供电线”。本教程需要两头都是 USB-A 公头的公对公数据线。

线材能够供电不代表一定能够传输数据。最可靠的判断方法是：完成后面的连接步骤，电脑运行 `adb devices` 能看到车机。如果电脑始终看不到车机，应先确认线材确实支持数据，再更换电脑 USB-A 接口测试。

## 二、先在车机上打开 USB 调试

这一步必须由你在车机上亲自完成，AI 无法隔空替你操作。

1. 打开车机的拨号界面；
2. 输入：

   ```text
   *#518200#*
   ```

3. 进入安卓设置后，找到“开发者选项”或“USB 调试”；
4. 确认“USB 调试”已经打开；
5. 如果出现风险提示，阅读后确认开启。

如果 USB 调试本来就是开启状态，不需要反复关闭再打开。

> 上述工程代码只在本项目对应的 2018 款长安逸动原厂车机上验证过。其他车型即使也是 Android 4.4.2，也不一定使用相同代码。

## 三、把车机 USB 切换成 Device 模式

电脑想通过 ADB 控制车机，车机必须作为一个被电脑识别的安卓设备，也就是 Device 模式。

1. 回到车机拨号界面；
2. 输入：

   ```text
   *#518121#*
   ```

3. 等待车机完成 USB 模式切换；
4. 把双 USB-A 公对公数据线的一头插入车机 USB-A 接口，另一头插入电脑 USB-A 接口；
5. 不要在中间接 USB 集线器、转接头或延长坞，第一次连接时尽量直接插入电脑接口。

“Device 模式”是给电脑调试车机用的。“Host 模式”则是车机读取 U 盘或直接连接其他 USB 设备时使用的。两者不是一回事。

安装完成以后，如果你还要让车机 USB 恢复 Host 功能，可在本车拨号界面输入：

```text
*#518120#*
```

无线使用 EadoPlay 时不需要电脑一直连接。切换 USB 模式不会卸载已经安装的软件。

## 四、在电脑上下载 ADB 工具

ADB 包含在 Google 官方的 `Platform-Tools` 中，不需要安装体积很大的 Android Studio。

1. 在电脑浏览器打开 Google 官方下载页面：

   [下载 Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools?hl=zh-cn)

2. 找到 Windows 版本；
3. 接受下载协议；
4. 下载文件，文件名通常类似：

   ```text
   platform-tools-latest-windows.zip
   ```

5. 在下载完成的 ZIP 文件上点击鼠标右键，选择“全部解压”；
6. 把解压得到的整个 `platform-tools` 文件夹放到 C 盘根目录；
7. 最终应能看到这个文件：

   ```text
   C:\platform-tools\adb.exe
   ```

请注意：

- 要解压整个文件夹，不能只把 `adb.exe` 单独拖出来；
- 如果最后变成 `C:\platform-tools\platform-tools\adb.exe`，说明多套了一层文件夹。可以把里面那层 `platform-tools` 移到 C 盘根目录；
- 尽量使用 Google 官方版本，不要下载网盘里的“魔改 ADB 工具箱”；
- Windows 可能隐藏 `.exe` 后缀，只要文件类型显示为“应用程序”即可。

## 五、下载 EadoPlay 安装包

1. 打开 EadoPlay 的发布页面：

   [EadoPlay GitHub Releases](https://github.com/LeoChase913/EadoPlay/releases)

2. 找到需要安装的版本；
3. 在该版本的“Assets”或“附件”区域下载扩展名为 `.apk` 的文件；
4. 建议把 APK 放到电脑桌面，路径更容易辨认；
5. 不要解压 APK，也不要修改 APK 内部文件。

例如，下载后的文件可能是：

```text
C:\Users\你的电脑用户名\Desktop\EadoPlay-r29.apk
```

你的用户名和 APK 文件名可能不同，这是正常的。后面要把真实路径告诉 AI。

### 怎么得到 APK 的准确路径

最简单的方法：

1. 在 Windows 文件资源管理器中找到 APK；
2. 按住键盘上的 `Shift`；
3. 对 APK 点击鼠标右键；
4. 选择“复制文件地址”或“复制为路径”；
5. 把复制出来的内容粘贴到记事本暂存。

复制结果一般类似：

```text
"C:\Users\lzc\Desktop\EadoPlay-r29.apk"
```

保留这个完整路径，稍后交给 AI。

## 六、第一次连接时允许电脑调试车机

在车机已经开启 USB 调试、已经切换 Device 模式，并且数据线已经连接电脑后，观察车机屏幕。

车机可能弹出“是否允许 USB 调试”或“是否允许此电脑调试”，并显示一串 RSA 密钥指纹。此时：

1. 勾选“始终允许使用这台计算机进行调试”；
2. 点击“允许”或“确定”；
3. 不要点击“取消”。

如果没有立刻弹窗，先不要慌。后面 AI 运行 `adb devices` 后，弹窗可能才出现。

如果电脑曾经连接过这台车机，而且之前已经勾选过“始终允许”，车机可能不会再次弹窗。

## 七、把安装工作交给 AI

到这里为止，你应该已经完成：

- 车机已打开 USB 调试；
- 车机已切换到 Device 模式；
- 车机和电脑已通过双 USB-A 公对公数据线连接；
- 电脑已有 `C:\platform-tools\adb.exe`；
- 电脑已有 EadoPlay APK；
- 你知道 APK 的完整路径。

接下来打开一个能够操作本机终端的 AI 对话，把本文第十二节的完整提示词发给它，并把里面的 APK 路径替换成你自己的真实路径。

### AI 操作时你要做什么

AI 开始后，不要离开车机。你需要配合以下事项：

1. 如果车机弹出 USB 调试授权，立即勾选“始终允许”并点击允许；
2. 如果 AI 说设备状态是 `unauthorized`，检查车机屏幕有没有授权弹窗；
3. 如果 AI 说没有发现设备，重新检查 Device 模式、数据线和电脑 USB 接口；
4. 如果 AI 要卸载旧版、清除数据、root、修改系统分区或删除其他应用，先拒绝并查明原因；
5. 安装过程中不要拔线、熄火或让车机断电；
6. AI 显示安装成功后，在车机桌面检查是否出现 EadoPlay 图标。

AI 应当一边执行一边告诉你结果。看到异常时，它应该停下来分析，不能连续执行一串更激进的命令。

## 八、AI 正常会经历哪些步骤

你不需要理解每条命令，但可以用下面的流程判断 AI 有没有乱操作。

### 第一步：确认工具和 APK 都存在

AI 会检查：

```text
C:\platform-tools\adb.exe
你提供的 EadoPlay APK 完整路径
```

如果任意一个文件不存在，AI 应停止并告诉你路径哪里有问题。

### 第二步：确认电脑能看到车机

AI 会运行：

```powershell
& 'C:\platform-tools\adb.exe' version
& 'C:\platform-tools\adb.exe' devices -l
```

设备状态必须是：

```text
device
```

其他状态的含义：

- 没有设备：电脑还没有通过 USB 找到车机；
- `unauthorized`：车机还没有允许这台电脑调试；
- `offline`：ADB 连接异常，需要重新启动 ADB 或重新插线。

设备不是 `device` 时，AI 不应该继续安装。

### 第三步：确认工程 ADB 写入权限

AI 会先查看当前身份，并通过创建后立即删除一个测试文件，检查 `/data/app` 是否可写。

本项目对应的原厂车机具有所需的工程权限。这个检查用于确认当前 ADB 确实连接到了正确的车机，并防止在连接或权限状态异常时继续写文件。

如果显示 `Permission denied`，AI 必须停止。不能为了继续安装而擅自 root、破解系统或关闭车机安全服务。

### 第四步：绕过厂商鉴权并安全写入 APK

确认权限满足后，AI 会：

1. 查询车机是否已经安装 EadoPlay；
2. 如果已经安装，取得旧 APK 的准确路径；
3. 把新 APK 上传到车机临时目录；
4. 先在 `/data/app` 中生成一个临时文件；
5. 设置本车需要的文件所有者和权限；
6. 使用同分区改名方式一次性替换正式 APK；
7. 等待安卓系统扫描并登记应用；
8. 删除本次上传的临时文件。

这样可以避免系统在 APK 还没有复制完整时就扫描到半个文件。

AI 不应该使用通配符删除文件，不应该执行 `rm -rf /data/app`，也不应该删除任何无法确认属于 EadoPlay 的文件。

### 第五步：验证是否真的安装成功

图标出现只是初步结果。AI 还会检查：

- 包名是否为 `com.eadoplay.carplay`；
- APK 是否已经被安卓系统登记；
- 实际版本号和版本名称；
- 应用能否启动；
- 上传到临时目录的 APK 是否已经清理。

确认这些都正常后，安装才算完成。

## 九、安装成功后怎么检查

1. 在车机桌面找到 EadoPlay 图标；
2. 点击图标，确认应用能够打开；
3. 进入 EadoPlay 设置，查看显示的版本号；
4. 如果使用 r29，在“设置 → 连接 → 自动连接”中可以看到：
   - “打开 EadoPlay 时连接”；
   - “打开 EadoPlay 时开启车机热点”。
5. 第一次使用前，先按软件界面完成 iPhone 蓝牙配对和连接设置。

如果图标出现但一打开就退出，不代表安装方法有问题，也可能是 APK 与车机系统、CPU 或组件不兼容。此时让 AI 抓取启动日志分析，不要反复覆盖 APK。

## 十、安装完成后的收尾

1. 确认 EadoPlay 可以打开；
2. 让 AI 确认车机临时目录中的本次安装文件已删除；
3. 保存这次安装的 APK，记住版本号；
4. 安装结束后即可断开电脑数据线；
5. 如果后续需要车机恢复 USB Host 模式，在本车拨号界面输入 `*#518120#*`；
6. 平时不再调试时，可以关闭 USB 调试；以后升级软件时再打开；
7. 无线使用 EadoPlay 不需要电脑持续连接，也不需要开启网络 ADB。

## 十一、常见问题

### 1. 输入工程代码没有反应

先确认是在车机自己的拨号界面输入，并且代码中的 `*` 和 `#` 没有输错。不同车型、不同固件的工程代码可能不一样，本文代码不能用于其他车机套用。

### 2. 车机能充电，但电脑看不到车机

充电只能证明线里有供电线路，不能证明支持数据。依次检查：

1. 是否已输入 `*#518121#*` 切到 Device 模式；
2. USB 调试是否开启；
3. 是否使用双 USB-A 公对公数据线，并确认线材支持数据传输；
4. 是否插错车机 USB 接口；
5. 更换电脑 USB 接口；
6. Windows 设备管理器里是否有未识别的 Android 或 ADB 设备；
7. 重新插线后再次运行 `adb devices -l`。

### 3. AI 说设备是 `unauthorized`

看车机屏幕，找到 USB 调试授权弹窗，勾选“始终允许”并点击允许。如果弹窗被其他界面挡住，先返回车机安卓桌面查看。

### 4. AI 说列表是空的

这说明问题还发生在连接阶段，与 APK 无关。不要继续尝试安装命令。重点检查 Device 模式、USB 调试、线材、接口和 Windows 驱动。

### 5. 为什么不尝试 `adb install`

未破解的原厂车机会通过厂商鉴权拒绝普通第三方应用安装，直接点击 U 盘 APK 和执行 `adb install` 都无法解决。APK 放在桌面、U 盘还是车机内部存储并不会改变这个鉴权结果。因此本文在确认工程 ADB 权限后，直接使用 `/data/app` 安装流程。

### 6. 提示签名不一致

不要直接卸载旧版。卸载可能清除 EadoPlay 的设置和配对信息。先让 AI 核对旧版和新版的包名、签名及版本，再由你决定是否备份后卸载。

### 7. 安装后没有立刻出现图标

先等待 10 至 20 秒，让安卓系统扫描 APK。AI 可以用 `pm path` 和 `dumpsys package` 检查。只有确认系统没有登记时，才考虑重启车机，不能一上来就反复覆盖文件。

### 8. 电脑提示找不到 `adb`

不要只输入 `adb`。让 AI 使用完整路径：

```text
C:\platform-tools\adb.exe
```

并检查是否因为解压后多了一层 `platform-tools` 文件夹。

### 9. 可以直接把 APK 放进 `C:\platform-tools` 吗

可以，但没有必要。APK 可以放在桌面或下载目录，只要把准确的完整路径告诉 AI 即可。

### 10. 需要 root 吗

本教程不需要 root。它使用的是本车已经开放的工程 ADB 权限。如果你的车机没有相同权限，本文不会教你强行 root 或破解系统。

## 十二、复制给 AI 的完整提示词

先把下面的“APK 路径”替换成你从 Windows 复制得到的真实路径，然后把整段内容发送给能够操作你电脑终端的 AI。

```text
我要在我本人拥有、并已授权调试的 2018 款长安逸动 Android 4.4.2 原厂车机上安装 EadoPlay。

我已经亲自在车机上完成以下操作：
1. 在车机拨号界面输入 *#518200#*，打开了 USB 调试；
2. 输入 *#518121#*，把车机 USB 切换到了 Device 模式；
3. 已使用两头都是 USB-A 公头、并支持数据传输的双 USB-A 公对公数据线，把车机直接连接到这台 Windows 电脑；
4. 如果车机出现 USB 调试授权弹窗，我会在车机上勾选“始终允许”并点击允许。

电脑上的 ADB 预计位于：
C:\platform-tools\adb.exe

需要安装的 APK 完整路径是：
【把这里替换成实际 APK 完整路径】

EadoPlay 包名是：
com.eadoplay.carplay

请直接协助我完成检查、安装和验证，并严格遵守下面的流程：

1. 先做只读检查，不要立即修改车机。确认 adb.exe 和 APK 文件真实存在，并告诉我检测结果。
2. 使用 adb 的完整路径运行 adb version 和 adb devices -l。
3. 只有设备状态明确显示为 device 才继续。若列表为空、显示 unauthorized 或 offline，停止安装并清楚告诉我应该在车机或电脑上做什么；不要猜测设备已经连接。
4. 运行 adb shell id，记录当前 ADB shell 身份，但不要因为身份不是 root 就擅自 root。
5. 直接检查工程 ADB 是否能写 /data/app。使用一个名称明确的临时测试文件进行 touch，并在同一条命令中立即删除；不要碰其他文件。
6. 如果 /data/app 写入测试返回 Permission denied 或结果不确定，停止并告诉我当前调试连接或工程权限异常。禁止 root、解锁 Bootloader、修改 /system、关闭厂商安全服务或使用来历不明的提权工具。
7. 如果 /data/app 确认可写，先运行 pm path com.eadoplay.carplay，查询是否存在旧版以及旧 APK 的准确路径。
8. 如果已有版本，必须使用 pm path 返回且明确位于 /data/app/ 的那个 APK 路径作为替换目标。如果没有旧版，首次安装目标使用 /data/app/eadoplay.apk。目标不在 /data/app/ 时必须停止。
9. 将电脑上的 APK 推送到 /data/local/tmp/EadoPlay-new.apk。确认 push 成功后，再继续。
10. 停止 EadoPlay 进程；把临时目录中的 APK 复制为 /data/app/.eadoplay.apk.tmp；复制完整后设置本车已验证的所有者 system.system 和权限 0644；最后在同一分区原子改名为第 8 步确认的正式目标，并执行 sync。
```

## 十三、如果没有能操作终端的 AI

如果你使用的 AI 只能聊天，不能操作本机终端，它无法真正替你安装。此时有两个选择：

1. 换用明确支持本地终端操作、且你已授权访问 `C:\platform-tools` 和 APK 路径的 AI；
2. 找懂 ADB 的人现场协助，并把本文交给对方作为操作边界。

不要把车机调试权限交给来历不明的远程控制软件，也不要让陌生人随意执行“一键 root”“全自动破解”脚本。

## 十四、一页纸检查清单

开始前逐项确认：

- [ ] 车辆已经停稳并保持供电；
- [ ] 已输入 `*#518200#*` 并打开 USB 调试；
- [ ] 已输入 `*#518121#*` 并切换 Device 模式；
- [ ] 使用的是两头均为 USB-A 公头、且支持数据传输的双 USB-A 公对公数据线；
- [ ] 车机已经连接电脑；
- [ ] `C:\platform-tools\adb.exe` 确实存在；
- [ ] EadoPlay APK 已下载且没有解压；
- [ ] 已复制 APK 的完整路径；
- [ ] 已准备好在车机上确认 USB 调试授权；
- [ ] 已把第十二节完整提示词交给能操作本机终端的 AI；
- [ ] AI 确认设备状态为 `device` 后才开始安装；
- [ ] 安装后已经核对版本并清理临时文件。

只要前面的准备工作完成，后续技术命令可以交给 AI；但车机屏幕上的 USB 调试授权、线材连接和工程模式切换，仍然必须由车主本人完成。
